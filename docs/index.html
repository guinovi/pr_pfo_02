Sistema de Gestión de Tareas con API y SQLite

Implementación completa de API REST en Flask, autenticación con contraseñas hasheadas (scrypt/PBKDF2), almacenamiento persistente en SQLite y cliente de consola interactivo.

📖 Documentación API 💡 Respuestas Conceptuales ⚡ Simulador Interactivo

🏗️ Arquitectura y Objetivos

El proyecto cumple con los 4 pilares fundamentales establecidos en la consigna:

1. API REST Funcional

Endpoints organizados para registro, login, consulta HTML y gestión de tareas.

2. Seguridad de Credenciales

Hasheo criptográfico unidireccional con sal mediante werkzeug.security.

3. Persistencia en SQLite

Base de datos relacional local con tablas para usuarios y tareas vinculadas.

4. Cliente de Consola

Interfaz CLI interactiva (cliente.py) con manejo de sesiones HTTP persistentes.

📡 Especificación de Endpoints

POST /registro

Registra un nuevo usuario en SQLite. Hashea la contraseña antes de guardarla.

Cuerpo JSON recibido:

{
  "usuario": "estudiante",
  "contraseña": "clave_segura_123"
}

Respuesta Exitosa (201 Created):

{
  "mensaje": "Usuario registrado exitosamente",
  "usuario": "estudiante"
}
POST /login

Verifica las credenciales contra el hash en SQLite e inicia sesión.

Cuerpo JSON recibido:

{
  "usuario": "estudiante",
  "contraseña": "clave_segura_123"
}

Respuesta Exitosa (200 OK):

{
  "mensaje": "Inicio de sesión exitoso",
  "usuario": "estudiante"
}
GET /tareas

Devuelve una página HTML de bienvenida (renderizada con motor Jinja2). Si el usuario cuenta con sesión activa, muestra además sus tareas pendientes.

Tipo de Contenido:

Content-Type: text/html; charset=utf-8
GET /api/tareas

Listado de tareas en formato JSON para el cliente en consola (requiere autenticación).

{
  "usuario": "estudiante",
  "tareas": [
    {
      "id": 1,
      "titulo": "Instalar dependencias",
      "descripcion": "pip install -r requirements.txt",
      "completada": 1,
      "fecha_creacion": "2026-10-05 14:00:00"
    }
  ]
}
POST /api/tareas

Crea una nueva tarea vinculada al usuario autenticado en SQLite.

{
  "titulo": "Nueva tarea",
  "descripcion": "Detalles opcionales"
}

💡 Respuestas Conceptuales

1. ¿Por qué hashear contraseñas?

Guardar contraseñas en texto plano es una de las vulnerabilidades más críticas en la seguridad informática. El hasheo de contraseñas es imprescindible por las siguientes razones:

  • Principio de función unidireccional (One-Way): Un algoritmo de hash criptográfico transforma cualquier texto plano en una cadena de longitud fija imposible de revertir matemáticamente. No existe una función que permita "deshashear" para obtener la clave original.
  • Mitigación ante filtraciones (Data Breaches): Si un atacante accede a la base de datos (por inyección SQL, backup expuesto o acceso indebido al servidor), solo obtendrá los hashes criptográficos y no las claves reales de los usuarios.
  • Protección del usuario en múltiples servicios: Gran parte de los usuarios reutiliza contraseñas en distintas plataformas. Si se expusieran en texto plano, el atacante podría vulnerar sus correos, bancos u otros servicios personales.
  • Salting contra ataques de tablas arcoíris (Rainbow Tables): Las librerías modernas como werkzeug.security aplican una "sal" criptográfica aleatoria única por cada usuario. Esto asegura que dos contraseñas idénticas generen hashes completamente distintos, inutilizando las tablas de búsqueda precalculadas y ataques masivos por diccionario.

2. Ventajas de usar SQLite en este proyecto

SQLite es el motor de base de datos relacional más embebido del mundo, y para este tipo de aplicación ofrece ventajas contundentes:

  • Cero configuración y sin servidor (Serverless): A diferencia de motores cliente-servidor como MySQL o PostgreSQL, SQLite no requiere instalar ni administrar un proceso demonio (daemon) separado ni gestionar puertos o permisos de red complejos.
  • Archivo único y portabilidad total: Toda la base de datos (tablas, índices, registros) se almacena en un único archivo de disco (gestor_tareas.db). Esto facilita copiar el proyecto, realizar backups instantáneos y transportarlo entre diferentes computadoras sin pasos previos.
  • Integrado nativamente en Python: Python incluye el módulo estándar sqlite3, eliminando dependencias externas de controladores o librerías de conexión para la base de datos.
  • Cumplimiento ACID: Pese a su ligereza, SQLite garantiza Atomicidad, Consistencia, Aislamiento y Durabilidad (ACID), protegiendo la integridad de los datos ante cortes o errores de ejecución.
  • Rendimiento óptimo para entornos educativos y prototipado: Para proyectos académicos, prototipos y aplicaciones con cargas ligeras o medianas, SQLite ofrece un acceso a disco de altísima velocidad con una huella de memoria insignificante.

💻 Cómo Ejecutar el Proyecto

  1. Clonar el repositorio: 
    git clone <URL-DE-TU-REPOSITORIO>
cd tp2
  2. Crear el entorno virtual e instalar dependencias: 
    python3 -m venv venv
source venv/bin/activate  # En Linux/Mac
# o en Windows: venv\Scripts\activate
pip install -r requirements.txt
  3. Iniciar el servidor Flask: 
    python3 servidor.py
    El servidor escuchará peticiones en http://127.0.0.1:5000.
  4. Ejecutar el cliente en consola: 
    python3 cliente.py          # Menú interactivo
python3 cliente.py --demo   # Demostración automatizada completa
  5. Ejecutar las pruebas unitarias automatizadas: 
    python3 test_servidor.py
