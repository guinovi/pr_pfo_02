Sistema de Gestión de Tareas

API REST en Flask, protección de credenciales con hash criptográfico, persistencia en SQLite y cliente de consola interactivo.

Endpoints API Respuestas Conceptuales Simulador Web

📡 Endpoints de la API

POST /registro

Registra un nuevo usuario en SQLite. Hashea la contraseña antes de persistirla en la base de datos.

Cuerpo JSON recibido: 
{
  "usuario": "nombre_usuario",
  "contraseña": "mi_clave_secreta"
}
Respuesta (201 Created): 
{
  "mensaje": "Usuario registrado exitosamente",
  "usuario": "nombre_usuario"
}
POST /login

Verifica las credenciales contra el hash en SQLite e inicia sesión con cookies firmadas.

Cuerpo JSON recibido: 
{
  "usuario": "nombre_usuario",
  "contraseña": "mi_clave_secreta"
}
Respuesta exitosa (200 OK): 
{
  "mensaje": "Inicio de sesión exitoso",
  "usuario": "nombre_usuario"
}
GET /tareas

Muestra una página HTML de bienvenida diseñada con Bootstrap por CDN. Si el usuario inició sesión, muestra saludo personalizado y sus tareas.

Content-Type: text/html; charset=utf-8

💡 Respuestas a las Preguntas Conceptuales

1. ¿Por qué hashear contraseñas?

Guardar contraseñas en texto plano es una de las fallas de seguridad más graves en el desarrollo de software. El hasheo es indispensable por las siguientes razones:

  • Función Unidireccional (One-Way): Un hash es un algoritmo matemático diseñado para funcionar en un solo sentido. Transforma cualquier texto plano en una cadena fija imposible de revertir matemáticamente para obtener la clave original.
  • Protección ante Filtraciones de Base de Datos (Data Breaches): Si un atacante vulnera el servidor o descarga el archivo SQLite, solo obtendrá hashes criptográficos y no las claves de los usuarios.
  • Defensa contra la Reutilización de Contraseñas: La mayoría de los usuarios utiliza la misma contraseña para varios servicios (bancos, correos, redes). Proteger sus claves evita que una brecha en nuestro sistema comprometa sus demás cuentas.
  • Salting contra Tablas Arcoíris (Rainbow Tables): Librerías como werkzeug.security añaden automáticamente una "sal" aleatoria única a cada contraseña. Esto evita que dos contraseñas idénticas generen el mismo hash y neutraliza ataques masivos con diccionarios precalculados.

2. Ventajas de usar SQLite en este proyecto

SQLite es un motor de base de datos relacional ligero y potente que presenta claras ventajas para este trabajo práctico:

  • Sin Servidor (Serverless) y Cero Configuración: A diferencia de MySQL o PostgreSQL, no requiere instalar ni mantener un servicio demonio corriendo en segundo plano ni configurar puertos o credenciales de conexión al servidor de base de datos.
  • Persistencia en un Archivo Único y Portabilidad: Toda la base de datos (tablas, índices y datos) se guarda en un único archivo (gestor_tareas.db). Esto hace que el proyecto sea 100% portable entre computadoras (Linux, Windows, macOS).
  • Integración Nativa en Python: Python incluye el módulo sqlite3 en su biblioteca estándar, eliminando la necesidad de instalar dependencias o drivers adicionales.
  • Cumplimiento de Estándares ACID: Garantiza Atomicidad, Consistencia, Aislamiento y Durabilidad, protegiendo la integridad de los datos ante cierres inesperados.
  • Rendimiento Óptimo para Entornos Académicos: Ofrece tiempos de respuesta inmediatos y un consumo de memoria mínimo, ideal para prototipos y sistemas de escala pequeña/mediana.
